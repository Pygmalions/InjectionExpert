# AGENTS Contribution Guidelines (for AI/LLM collaborators)

This document defines mandatory rules and practical guidance for using LLMs (e.g., Copilot, ChatGPT, etc.) to generate code and tests in this repository, ensuring consistent quality, maintainability, and reviewability.

## Scope
- Applies to:
  - Any source code, unit tests, scripts, or documentation substantially generated by an LLM;
  - Commits where refactoring or large-scale changes are primarily produced by an LLM.

## Core Principles
1. Traceability: LLM-generated content must be attributable to its tool and model.
2. Maintainability: Generated code should have clear naming, sound structure, and necessary comments.
3. Verifiability: Generated or modified code must be accompanied by reliable tests; avoid brittle, constant-based assertions.

## Mandatory Rules (must follow)

1. Agent comment at the top of files and above AI-generated test methods
   - All LLM-generated content must include a comment either at the very beginning of the file or immediately above each AI-generated test method in the form: "Agent: ToolName, ModelName".
   - Examples (C#):
     - Single file:
       // Agent: Copilot, GPT-5-mini
       // Additional notes (optional)
     - Test method:
       // Agent: Junie, gpt-5-2025-08-07
       [Test]
       public void Example_Test() { /* ... */ }
   - Placement:
     - Files: the very first line of the file (or immediately after a copyright/license header, before the first using).
     - Test methods: place the comment immediately above the method (placing it above attributes such as [Test] is acceptable).
   - If different LLMs generated different parts of the same file, the file-level author comment still applies; optionally add inline notes above specific blocks.

2. Unit tests should avoid constant test inputs
   - NUnit tests generated by an LLM should use NUnit's random value providers whenever possible to improve robustness and reduce overfitting to constants.
   - Use TestContext.CurrentContext.Random to generate data, for example:
     - int sample = TestContext.CurrentContext.Random.Next(1, 1000);
     - long count = TestContext.CurrentContext.Random.NextInt64();
     - double ratio = TestContext.CurrentContext.Random.NextDouble();
   - Random boundaries guidance:
     - Provide explicit bounds to avoid inadvertent out-of-range values;
     - For strings/collections, randomize the length first, then the contents;
     - For deterministic scenarios, use TestCaseSource or parameterized combinations to cover boundaries and exceptional paths instead of tying assertions to hard-coded constants.

3. Variable naming conventions (C#)
   - Follow C# naming conventions:
     - Public types/members: PascalCase (e.g., CustomerRepository).
     - Private fields (if prefixed): _camelCase; otherwise camelCase.
     - Local variables and parameters: camelCase.
     - Constants: PascalCase or UPPER_CASE_WITH_UNDERSCORES (follow project-specific conventions first).
   - Names must be meaningful. Avoid:
     - Single letters (e.g., i, x, y) except in very small, obvious loop counters;
     - Obscure abbreviations or invented terms;
     - Domain-irrelevant or vague names (e.g., tmp, data1).
   - Method names should express intent; boolean names should start with Is/Has/Can/Should to enhance readability.
   - For unused lambda parameters, use the discard name "_" to make intent explicit (e.g., items.Select(_ => 0)).

4. Language for new/changed files
   - Regardless of the language used in a user's request, files added to this project should be written in English whenever reasonably possible.
   - Exceptions should be rare and justified (e.g., localization resources), and must be noted in the PR description.

## Code Style and Structure Recommendations
- Small functions, single responsibility: split complex logic into reusable, focused methods.
- Explicit exceptions: handle predictable exceptional paths explicitly or cover them with unit tests.
- Comments and documentation:
  - Comment non-obvious logic, public APIs, and constraints;
  - Keep comments in sync with the implementation to avoid stale information.

## Testing Guidelines
- Prefer parameterized tests ([TestCase], [TestCaseSource], [Values], [Range], etc.).
- Favor randomized inputs with clear assertions; focus on boundary values, nulls, and extreme cases.
- If you need a fixed random sequence for reproducibility, set a seed at class or method level but avoid binding assertions to specific constant outputs (unless in intentionally deterministic scenarios).

## Submission Process and Review Checklist
Before submitting/raising a PR, ensure:
- [ ] LLM-generated files include an author comment at the very top (Author: ToolName, ModelName).
- [ ] Unit tests avoid unnecessary hard-coded constants and use TestContext.CurrentContext.Random for inputs where appropriate.
- [ ] Variable names follow C# conventions and carry business meaning; no arbitrary abbreviations or single-letter names.
- [ ] New/added files are written in English (justify any exceptions in the PR description).
- [ ] Adequate test coverage for new/changed code, including normal and exceptional paths.
- [ ] Static analysis and formatting checks pass (follow this project's EditorConfig/rules).

## Example Snippets

C# source file header:

```csharp
// Agent: Copilot, GPT-5-mini
using System;

namespace Demo
{
    public class OrderCalculator
    {
        public decimal CalculateTotal(decimal unitPrice, int quantity)
        {
            if (quantity < 0) throw new ArgumentOutOfRangeException(nameof(quantity));
            return unitPrice * quantity;
        }
    }
}
```

NUnit test example (randomized input):

```csharp
using NUnit.Framework;

namespace Demo.Tests
{
    public class OrderCalculatorTests
    {
        // Agent: Junie, gpt-5-2025-08-07
        [Test]
        public void CalculateTotal_WithRandomValues_IsNonNegative()
        {
            // Randomly generate unit price and quantity
            var unitPrice = (decimal)TestContext.CurrentContext.Random.NextDouble() * 1000m; // 0 ~ 1000
            var quantity = TestContext.CurrentContext.Random.Next(0, 1000); // 0 ~ 999

            var calculator = new OrderCalculator();
            var total = calculator.CalculateTotal(unitPrice, quantity);

            Assert.That(total, Is.GreaterThanOrEqualTo(0m));
        }
    }
}
```
